# 模块接口约定 v0

本文件给五位负责人提供共同交接格式，当前是文档约定，没有实现。#1 的接口检查点先确认这些字段；课程数据取得后由组长核对并更新。变更共享字段需要同步对应 issue 和消费者。

## 1. 输入与版本准备

课程 JSONL 预期包含 `idx`、`commit_url`、`target`、`func`，具体类型和配对标识待真实文件确认。`idx` 保留原值，不重编号；暂按字符串或整数处理。

成员 B 的准备模块接收原始课程样本，用 `target` 选择唯一快照：1 选修复提交父版本，0 选修复提交版本。多父提交或输入函数与目标版本不一致时显式报错，交组长确认课程选择规则，不猜测。

Web 单样本输入函数、修复提交链接，并明确选择函数所在版本：“该提交”或“父提交”，不自动默认。准备请求用 `revision=commit` 或 `revision=parent` 表达选择；选择只用于准备层，不进入 Agent 请求或工具可读元数据。无选择时要求补齐输入，不能凭修复链接直接假定函数属于修复后版本。Bot 的定点请求使用显式指定的提交，向准备层传 `revision=commit`。

准备模块输出给检测层：

| 字段 | 含义 |
| --- | --- |
| `idx` | 样本标识，保持输入值 |
| `func` | 待测 C/C++ 函数文本 |
| `snapshot_ref` | 指向已准备单版本快照的不透明引用，不包含标签或 parent/fixed 语义 |

真实标签、配对关系和用于版本解析的修复提交信息由准备/评测层保留；不能作为 Agent 可读元数据。工具结果中的路径相对于当前快照，不能暴露缓存路径中的标签信息。

## 2. RAG 检索

成员 A 提供 `search_cases(query, limit)` 能力，组长注册为 Agent 工具。每条结果包含 `case_id`、`content`、`source`，以及数据中实际存在的项目/CVE/CWE 信息。`source` 可追溯至本地历史数据文件和记录标识。排序与分数若有明确含义可返回，不编造相关性概率。

只有课程历史数据能进入索引。历史漏洞/修复对及其提交说明可以检索；待测集不能入库。无相关结果时返回明确的空结果，读取或索引失败返回错误，两者不得混淆。

## 3. 仓库上下文工具

成员 B 提供下列能力，具体代码 API 在 #1 检查点与 #4 对齐：

| 能力 | 最小输入 | 输出 |
| --- | --- | --- |
| 代码搜索 | `snapshot_ref`、查询文本 | 匹配路径、行号、片段 |
| 文件读取 | `snapshot_ref`、相对路径、行区间 | 原文、路径、起止行号 |
| 定义/调用位置查找 | `snapshot_ref`、符号名称 | 匹配证据；不确定关系如实标记 |

行号使用 1 起始。结果明确区分“未找到”和“读取失败”。搜索或解析的实际覆盖范围写入文档，不把文本匹配宣称为完整调用图。所有工具都限定在当前快照，不能读取另一版本或 Git 历史。

## 4. 检测任务 API

组长负责 API 与共享类型。计划接口如下：

| 接口 | 用途 |
| --- | --- |
| `POST /api/detections` | 提交一个 `idx`、`func`、`snapshot_ref` 检测请求 |
| `POST /api/batches` | multipart 上传课程 JSONL，经准备层逐条处理 |
| `GET /api/tasks/{task_id}` | 查询任务状态、完成计数和失败项 |
| `GET /api/tasks/{task_id}/events` | SSE 订阅过程事件 |
| `GET /api/tasks/{task_id}/reports` | 获取已完成报告及明确的失败项 |
| `GET /api/tasks/{task_id}/result.jsonl` | 导出完成且覆盖全部输入的课程结果 |
| `POST /api/snapshots` | 接收 `commit_url` 和明确的 `revision`（`commit` / `parent`），准备手动输入或 Bot 的单版本快照 |

创建任务返回 `task_id`。任务状态为 `queued`、`running`、`completed` 或 `failed`。批量包含失败样本时任务不算成功完成，状态及错误保留已有完成结果。

接口错误使用 `code`、`message`，已关联任务或样本时带 `task_id` / `idx`。字段校验及具体 HTTP 响应在 #5 实现时随 API 文档更新。

## 5. SSE 事件

事件类型：`task_status`、`retrieval`、`repository_read`、`sample_completed`、`error`、`task_completed`。SSE 的 `event` 为类型，`data` 为 JSON。

公共字段为 `task_id`、`seq`、`timestamp`、`type`、`payload`；关联样本时包含 `idx`。`seq` 在任务内递增，供 UI 排序；v0 不承诺断线回放，重连后用状态和报告接口确认结果。

- 检索事件包含查询、返回的 `case_id` 和来源摘要。
- 仓库事件包含工具名称、查询/读取参数、返回路径/行号及结果摘要。
- 完成事件关联报告；错误事件包含可定位的失败原因。

记录公开的操作、证据和判定摘要，不要求展示模型私有思维链。SSE 与报告记录不得丢失工具错误或伪造调用。

## 6. 报告与课程导出

完整报告：

| 字段 | 含义 |
| --- | --- |
| `idx` | 输入样本标识 |
| `prediction` | 成功检测后给出的整数 0 或 1 |
| `reason` | 基于当前证据的判定理由 |
| `evidence` | 引用的历史案例和代码位置，关联来源标识 |
| `trace` | 按时间/序号排列的检索及仓库调用记录 |

失败样本单独返回状态和错误，不生成伪造的二元报告。课程导出只从成功报告提取 `idx` 和 `prediction`，保持输入顺序及标识类型。

仅格式示意，以下标识不属于课程数据，也不是实际检测结果：

```json
{"idx":"synthetic-demo","prediction":1}
```

导出前检查输入 `idx` 唯一性、覆盖、预测取值及失败项。任何缺失/重复/失败都阻止成功导出并说明原因，不静默补零或跳过。需要诊断时使用完整报告接口。

成员 D 的评测模块接收 `result.jsonl` 和课程评测数据；真实标签只在此处参与统计。课程脚本为评分依据，不猜测样本配对关系。
